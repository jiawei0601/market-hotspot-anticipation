# Probe 0008: 板塊歸屬證據定日登記簿 — 來源探查

狀態：探查完成（供 ADR 0008「板塊歸屬證據定日登記簿」決策參考）
探查日期：2026-07-04
探查方式：實際打 API/curl（Wayback CDX、MOPS 電子資料查詢作業）+ WebSearch/WebFetch 實測現行網頁結構，
非查文件猜測。所有數字均為本次執行時親眼看到的結果。

## 背景

CPO／矽光子／光通訊／散熱供應鏈追蹤的核心問題：「某檔股票屬於某題材」這件事本身沒有客觀、
權威、按日期可回溯的單一真相來源——不像財報數字有 MOPS 強制申報，「板塊歸屬」多半只存在於
概念股網站的動態分類頁，而這些頁面隨時可能重新編輯、沒有版本歷史。本探查回答：
「這件事有哪些可程式化取得、可留存、可按日期回溯的證據來源」，為 ADR 0008 的
「板塊歸屬證據定日登記簿」設計提供依據。

## 1. Wayback Machine CDX API（各平台概念股頁快照密度比較）

### 1a. MoneyDJ「同業股價表現」分類頁

**端點**：`https://www.moneydj.com/z/zh/zha/zh00.djhtm?a=C023500`（光通訊）、
`https://www.moneydj.com/z/zh/zha/zh00_C023153.djhtm`（散熱模組，經 WebSearch 找到的實際存在頁面）

這兩個 URL 是透過 WebSearch 找到的現行 MoneyDJ 頁面，非猜測。實測解析：光通訊頁（今日快照）可
解析出 25 檔股號+名稱（`Link2Stk('AS3450');">3450聯鈞` 等 pattern），散熱模組頁可解析出 18 檔，
證實頁面結構確實含成分股清單、可程式化解析（HTML 為 Big5 編碼，需 `iconv -f BIG5 -t UTF-8` 轉碼後
才能正確 grep 中文字串，直接 grep 會被判定為 binary 檔案跳過比對）。

**CDX 查詢結果（`from=2015&to=2026`，`output=json`）**：

- 光通訊頁 `zh00.djhtm?a=C023500`：**全歷史僅 1 筆快照**（`20240906170953`，2024-09-06）。
- 散熱模組頁 `zh00_C023153.djhtm`（底線變體 URL）：**0 筆快照**。
- 改用同分類代碼但無底線變體 `zh00.djhtm?a=C023153`：**同樣 0 筆**。
- 用 `matchType=prefix` 對整個 `zh00.djhtm` 路徑家族查詢並用 `filter=urlkey:.*c0235.*` /
  `.*c0231.*` 篩選鄰近分類代碼，證實**光通訊/散熱這兩個特定分類代碼本身幾乎沒有被 Wayback
  針對性存檔**——鄰近代碼（如 `C023120`）同樣只查到 1 筆（2024-05-06）。
- 對照組：`zh00.djhtm?a=C011010`（其他產業分類）在 `prefix` 查詢的前 50 筆結果中就出現了
  10 筆以上（2015-2016 年密集），證實 Wayback 爬蟲有抓過這個頁面模板整體，只是「光通訊」
  「散熱模組」這兩個具體分類代碼恰好落在爬蟲抓取覆蓋率之外，並非整個 MoneyDJ 站台都稀疏。

**深度解析測試**：對唯一的光通訊頁快照（2024-09-06）實際下載並解析：
`curl -s "http://web.archive.org/web/20240906170953/https://www.moneydj.com/z/zh/zha/zh00.djhtm?a=C023500"`
成功解析出 27 檔股號+名稱清單（含 `3450聯鈞`——本專案 12 檔清單之一），與 2026-07 現行版本（25 檔）
比對可見成分股確有異動：2024 年版多了「3447展達」「4905台聯電」「3712永崴投控」，少了「8045達運光電」。
**這證明快照 HTML 確實可解析出歷史時點的成分股清單，但因全歷史僅有這 1 筆，無法做「2 個不同年份」的
深度比較**——原計畫的「挑 2022/2023 一筆、2025 一筆」在光通訊頁上不可行，因為 2022-2023 年間該頁
完全沒有被存檔過。

### 1b. CMoney「概念股」頁

**端點**：`https://www.cmoney.tw/forum/concept/C50911`（光通訊概念股，WebSearch 找到）、
`https://www.cmoney.tw/forum/concept/C50800`（散熱模組概念股，WebSearch 找到）

**CDX 結果**：
- 光通訊概念股 C50911：**2 筆快照**（2025-08-13、2025-12-06）。
- 散熱模組概念股 C50800：**1 筆快照**（2025-01-16）。

密度優於 MoneyDJ（2-3 筆 vs 0-1 筆），但仍遠不足以支撐月度回溯——CMoney 平台本身在
2026-07 之前的存檔起點也晚（最早僅 2025-01），無法回溯到 2022-2023 年。

### 1c. 玩股網（wantgoo.com）

**探查結果**：WebSearch 多次嘗試查詢「CPO 概念股」「矽光子 概念股」在玩股網的專屬 index 頁面，
**查無明確對應的 URL**（玩股網用 `wantgoo.com/index/^{三位數字}/stocks` 格式的概念股頁，
搜尋結果只找到「不斷電限電」「智慧電網」「矽晶圓」等其他主題的 index 編號，沒有找到 CPO/矽光子/
散熱專屬編號）。改用 `matchType=domain` + `filter` 對整個 `wantgoo.com` 域名下 `index/*/stocks`
路徑做 CDX 掃描，確認這類頁面在 Wayback 上**存在但同樣稀疏**：抽樣看到的每個 index 編號
（如 `^033`、`^034`、`^070`、`^101`）在 2023-2024 年間都只各有 1 筆快照，同 MoneyDJ 的稀疏模式。

**結論：查無玩股網 CPO/矽光子/散熱專屬頁面 URL**，且即使找到具體編號，比照同域名其他 index
頁的存檔密度，預期同樣稀疏，不值得再花時間深入查證。

## 2. 台灣指數公司（taiwanindex.com.tw）

**WebSearch 找到的指數**：「TIP Taiwan Semiconductor Total Market Index」（臺灣全市場半導體指數，
`IX0143`）與「臺灣全市場半導體精選30指數」（`IX0154`）。

**WebFetch 實測 `IX0143` 頁面**：指數全名確認，但頁面**未提供成分股清單下載連結**，僅提供
Index Rules 文件與歷史績效數據；成分股異動走「Periodic Review」（定期審查，3/6/9/12月），
無具體異動公告查詢功能於本頁直接呈現。

**指數定期審核公告**（`taiwanindex.com.tw/news/407`，2026-03-18 生效）：WebFetch 實測發現公告
**確實存在且有歷史頁面**，但**僅列出指數名稱與代號（如 00904、00919、00929、009802），
不含具體成分股股號/名稱異動明細**；異動明細需另外下載「技術通知」PDF（本次未逐一下載驗證
PDF 內容，僅確認公告頁本身存在且結構為「總覽 + 連結技術通知」）。

**是否有光通訊/散熱專屬主題指數**：**查無**。

- 原本 WebSearch 索引到的「Thematics 主題式指數分類頁」路徑（`taiwanindex.com.tw/index/indexList?pid=6`）
  實測回應 **404**（該路徑已失效，網站結構已改版，WebSearch 索引到的是舊連結）。
- 改查現行 `taiwanindex.com.tw/en/indexes` 頁面，關鍵字掃描（grep `半導體|光通訊|網通|散熱|
  電子零組件|AI|Semiconductor|Optical|Thermal|Networking`）找到的是**「AIEX Index Series」**——
  這是 TWSE 官方「產業別股價指數」的官方指數化版本（如 `AIEX Optoelectronics Sub-Index`光電業、
  `AIEX Electronics Sub-Index`電子業、`AIEX Other Electronics Sub-Index`其他電子業、
  `AIEX Communications Technology and Internet Sub-Index`通信網路及網際網路業等），
  粒度與既有 probe-0007 / ADR 0007 用的 `industry_category` 粗分類體系相同（半導體業、光電業、
  電子零組件業等），**沒有找到任何「CPO」「矽光子」「散熱模組」這種細分主題的官方指數**。

**結論：半導體有官方指數（E2 級證據可用，但僅限「半導體業」這個粗分類，非 CPO 細分題材）；
光通訊/散熱/CPO 沒有對應主題指數，此路徑對這幾個細分題材是查無、走不通的**。

## 3. MOPS（doc.twse.com.tw）歷史文件程式化存取

**實測對象**：雙鴻（3324）2022年度年報（民國111年度，2023年股東會通過）、
雍智科技（6683）2021年度年報（民國110年度，2022年股東會通過）。

### 3a. 查詢流程（實測確認）

**第一步：GET 查詢**
```
GET https://doc.twse.com.tw/server-java/t57sb01?step=1&colorchg=1&co_id=3324&year=112&mtype=F
```
回應為 Big5 編碼 HTML（純 `curl` 直接抓取即可，**無需 session cookie、無需 Referer、無驗證碼**），
內容為一個表格，逐列列出該公司該年度所有已申報電子檔案，含「股東會年報」「開會通知」「議事手冊」
等多種資料類型，每列附精確檔名（如 `2022_3324_20230602F04.pdf`）與檔案大小（Bytes 精確到個位數）。

實測發現一個查詢陷阱：`year=112` 對應的股東會相關資料列表中，「股東會年報」實際檔名是
`2022_3324_...`（檔名開頭年份=2022=民國111年度年報，在112年股東會通過並申報）——**MOPS 的
`year` 參數對應「申報/股東會年度」，不直接等於「年報所屬會計年度」，兩者常差一年，實測时
必須看檔名裡的西元年份而非查詢用的 `year` 參數**，此為程式化取用時的重要細節。

**第二步：POST 換取臨時下載連結**
```
POST https://doc.twse.com.tw/server-java/t57sb01
Body: colorchg=1&step=9&kind=F&co_id=3324&filename=2022_3324_20230602F04.pdf
```
回應同樣是 Big5 HTML，內含一個**帶時間戳記的臨時連結**，例如：
`/pdf/2022_3324_20230602F04_20260704_152623.pdf`（時間戳 `20260704_152623` 即本次請求發起時刻）。

**驗證直接猜測 URL 是否可行**：實測對不帶時間戳的猜測 URL
（`https://doc.twse.com.tw/pdf/2022_3324_20230602F04.pdf`）直接 GET，回應 **404**。
證實**必須先走過 POST 流程換取當次專屬的臨時連結，不能繞過**。

**第三步：GET 下載 PDF**
```
GET https://doc.twse.com.tw/pdf/2022_3324_20230602F04_20260704_152623.pdf
```
**實測結果：`STATUS:200 SIZE:6668570`**，`file` 指令確認回傳為
`PDF document, version 1.7 (zip deflate encoded)`，`strings` 檢查內容含「3324」股號與
`auras.com.tw`（雙鴻英文網域）、`mops.twse.com.tw` 等字串，確認下載內容正確為雙鴻年報本體，
且檔案大小 6,668,570 bytes 與查詢頁面顯示的檔案大小欄位完全吻合。

### 3b. 第二檔複現測試（6683 雍智科技）

同一套三步流程（GET 查詢 → POST 換取臨時連結 → GET 下載）對雍智科技（6683）2021年度年報
（`2021_6683_20220627F04.pdf`）完整複現：POST 回應給出臨時連結
`/pdf/2021_6683_20220627F04_20260704_152734.pdf`，下載 **`STATUS:200 SIZE:2272503`**，
`file` 確認為 `PDF document, version 1.6`，與查詢頁顯示大小完全吻合。

### 3c. 結論

**可穩定用程式（curl）拿到年報 PDF，且流程可重複、非單一個股特例。** 具體要點：

- 需要 GET（查文件清單）→ POST（換臨時連結）→ GET（下載本體）三段式流程，**不能只靠一次
  GET 猜檔名直接下載**（會 404）。
- **無需 session cookie**：本次所有請求都是全新的 `curl` 呼叫，沒有攜帶任何 cookie，
  三段式流程仍全部成功，代表伺服器端沒有做 session 綁定檢查。
- **無需 Referer 檢查**：同樣沒有帶 Referer header，請求仍成功。
- **無驗證碼**：全程無 CAPTCHA 或任何人機驗證關卡。
- 臨時連結**帶時間戳**，經驗證不帶時間戳的裸檔名 URL 會 404，估計臨時連結有時效性（本次
  測試未刻意等待驗證失效時間，僅確認「必須走完整流程換得的連結」而非「猜檔名」可行）。
- 查詢用的 `year` 參數是「申報年度」不是「年報所屬會計年度」，程式化批次抓取時需注意此
  一年落差，並以回應中檔名裡的西元年份為準，不能只信賴查詢參數本身。

## 4. 12 檔既有清單的證據等級快查

方法：對每檔用 WebSearch 查詢「{股號} {名稱} CPO」「{股號} {名稱} 散熱 概念股」等關鍵字，
依搜尋結果**是否包含公司自身正式文件（法說會/公告/年報）明確描述相關業務**判定等級。
本輪為 WebSearch 摘要層級的快查，非逐一原始出處的人工核實，等級判定僅供 forward 流程的
起點參考，不構成最終定論。

## 5. 證據留存方式取捨評估

基於前 4 項實測經驗，三種留存方式的優缺點：

**(a) 只存 Wayback 快照 URL**

- 優點：零額外儲存成本，URL 本身自帶時間戳（如 `web.archive.org/web/20240906170953/...`），
  理論上人皆可回頭驗證。
- 缺點（本次實測直接證實）：**前提是快照必須存在**。第1項已證實 MoneyDJ/CMoney/玩股網的
  概念股分類頁快照密度極低（0-2筆全歷史），代表「被動指望 Wayback 已經幫你存了」在這幾個
  平台上大機率落空——如果現在才想到要記錄某檔股票的板塊歸屬，去 Wayback 查歷史快照，
  很可能查無資料。此方式對「回填」幾乎無用，只有在快照恰好存在時才有效。

**(b) 本地存 HTML/PDF 摘要**

- 優點：不依賴第三方網站的存檔意願或時效，一旦存了就是永久掌控在自己手上；MOPS 年報 PDF
  已證實可穩定程式化下載（第3項），存一份本地副本成本低（單檔數MB內）且內容完整可供
  日後全文搜尋比對。
- 缺點：占用本地空間（雖然對年報 PDF 這種量級不是問題，2-7MB/檔）；本地存檔本身不像
  Wayback 有第三方公證時間戳的公信力，若要對外舉證「這是某年某月的真實網頁」，自存 HTML
  的可信度不如第三方時間戳服務；且概念股網站（MoneyDJ等）的 HTML 若不主動去抓，同樣無法
  回溯——本地存檔只解決「forward 起點以後」的問題，不解決「現在才想查歷史」的問題。

**(c) 兩者並存**

- 優點：Wayback URL 作為「若剛好存在即可用的免費驗證管道」，本地存檔作為「保證有」的主力
  依據，兩者互補；對 MOPS 年報這類本來就可信、有官方時間戳（申報日期）的文件，本地存檔
  本身已足夠不需要額外 Wayback 佐證；對 MoneyDJ/CMoney 這類無官方時間戳、易變動的概念股
  分類頁，才需要主動送出快照存檔請求（Wayback 提供 Save Page Now API）以強制產生一筆
  「forward 之後」的可信快照。
- 缺點：維護成本最高——需要維護兩套存取邏輯（讀本地檔 + 視情況查 Wayback API），且如果
  兩者對同一時點的資料有出入（例如本地存檔記錄的內容與後來查到的 Wayback 快照不同），
  需要額外邏輯處理版本衝突判斷「以哪個為準」。

**取捨建議**：MOPS 年報/法說會等有官方時間戳的正式文件，**本地存檔即足夠**，不需要疊加
Wayback；MoneyDJ/CMoney 等無版本控制的概念股分類頁，**兩者並存**——本地存一份現況快照
作為主力證據，同時呼叫 Wayback Save Page Now API 產生一筆公開時間戳記錄，成本增量小
（一次 API 呼叫），換取未來若本地檔案遺失時仍有外部佐證管道。

## 建議

### 首選證據來源組合（forward 凍結用）

依本次實測的可行性與證據強度排序：

1. **公司法說會簡報/年報原文（MOPS 或公司官網 IR 專區）**——第3項證實 MOPS 可 100% 程式化
   下載，且是唯一能達到 E1 等級（公司自身正式文件佐證）的來源。forward 起點後，新股票納入
   板塊歸屬判定應**優先嘗試找到公司自身法說會簡報或年報中明確提及該題材關鍵字**（如「CPO」
   「矽光子」「共同封裝光學」原文字樣），而非停留在二手新聞轉述。
2. **台灣指數公司官方指數成分股**（若該題材剛好有對應主題指數，如半導體業）——第2項證實
   半導體有官方指數可用（E2），但 CPO/矽光子/散熱目前**沒有**專屬主題指數，此路徑對這幾個
   細分題材暫時用不上，僅在題材剛好對應到官方「產業別股價指數」的粗分類時可用。
3. **MoneyDJ/CMoney 概念股分類頁**（E3，輔助/交叉驗證用）——第1項證實這兩個平台的頁面本身
   可程式化解析出成分股清單（含股號+名稱），適合作為「多重來源交叉比對」的輔助訊號，
   但**不能單獨作為唯一證據**，且必須是 forward 主動存檔（見下），不能指望被動查到歷史快照。

### forward 凍結的具體流程建議

1. **月度排程**：每月對 universe 快照中的每檔股票（或至少對「新納入 universe 但尚未做過
   板塊歸屬判定」的股票）跑一次證據查核。
2. **查核順序**：(a) 先查該股近期是否有法說會簡報/年報提及題材關鍵字（可從 MOPS 或公司
   IR 頁面抓取，若命中記為 E1）→ (b) 查台灣指數公司是否有對應主題指數收錄該股（若該題材
   剛好有官方指數，記為 E2）→ (c) 查 MoneyDJ/CMoney 概念股分類頁是否收錄（記為 E3）。
3. **留存內容**：對命中的每個來源，存入一筆記錄（建議格式如
   `{stock_id, sector_tag, evidence_level, source_url, source_snapshot_url_or_local_path,
   checked_date, matched_keyword_or_excerpt}`），**同時**：
   - 對有官方時間戳的文件（MOPS PDF）：本地存檔案（依第5項建議 (a)）。
   - 對無版本控制的概念股頁（MoneyDJ/CMoney）：呼叫 Wayback Save Page Now API
     （`https://web.archive.org/save/{url}`）主動要求存檔，同時本地存一份 HTML 快照
     （依第5項建議 (c) 兩者並存）。
4. **不可變性**：每月的查核結果寫入獨立的按月快照檔（比照 ADR 0007 的 `universe.json` 模式），
   一旦寫入即不可覆蓋，若之後發現該股題材歸屬變動（如新增/剔除），用新的月份快照記錄變動，
   不回頭竄改舊快照——這樣「某股在某月被判定屬於某題材」本身就是一筆有時間戳的 PIT 證據，
   不因後續認知更新而追溯修改。

### 歷史回填的可行深度（誠實評估，不樂觀高估）

**結論：歷史回填非常有限，不建議依賴 Wayback 快照做系統性回填。**

- 第1項證實 MoneyDJ/CMoney/玩股網的概念股分類頁快照密度極低（全歷史 0-2 筆，且多數集中
  在 2024下半年到2025年），**2022-2023年間的快照幾乎不存在**，代表「回推到 2022 或 2023 年，
  當時哪些股票被歸類為 CPO/散熱概念股」這件事，**在 MoneyDJ/CMoney/玩股網這幾個來源上
  基本上查不到**，不是「資料少但還能用」，而是「絕大多數月份直接是空白」。
- MOPS 年報/法說會雖然本身可回溯到公司上市以來的所有年度申報（第3項證實流程對任意
  股號+年度組合可重複），**但年報/法說會內容本身多半在該題材成為市場焦點之前不會主動
  提及**——例如 2022 年的年報不太可能討論 2025-2026 年才熱門的 CPO 議題，這不是資料
  「回填」問題，而是「當時的正式文件裡本來就沒有這個資訊可回填」，屬於題材本身的
  時效性限制而非資料源限制。
- **較誠實的回填深度結論**：MOPS 年報/法說會可以回填到任意历史年度，但只在「該年度該公司
  剛好在文件中提及相關業務」時才有意義；對 CPO/矽光子這類 2025-2026 年才興起的新興題材，
  **實質上可回填的深度可能不超過 1-2 年**（即題材本身開始被公司提及、媒體開始討論的起點
  附近），更早的年份即使 MOPS 文件抓得到，內容裡也大概率沒有相關字樣可比對，不應宣稱
  「MOPS 可回溯到上市第一年」就等於「板塊歸屬可回填到上市第一年」，兩者是不同的事。
- 對「散熱」這種較成熟、非全新題材（相對 CPO 而言，散熱模組/液冷產業存在已久），回填的
  可行深度可能略優於 CPO，但本次探查未實測驗證此推論，**不宜在缺乏實測基礎下逕自宣稱
  散熱題材可回填更早**，僅記錄為待後續驗證的假設。

**已知缺口需誠實聲明**：

1. Wayback 對 MoneyDJ/CMoney/玩股網概念股分類頁的存檔密度嚴重不足，無法支撐月度回溯，
   僅能作為 forward 之後主動存檔的輔助管道。
2. 台灣指數公司目前沒有 CPO/矽光子/散熱專屬主題指數，E2 級證據對這幾個細分題材目前不可得，
   僅半導體粗分類有官方指數可用。
3. 12 檔既有清單的證據等級快查（第4項）僅為單輪 WebSearch 摘要層級判定，非逐一核實原始
   法說會/公告全文，等級可能隨更嚴謹的原始文件核對而升降，不構成最終定論。
4. MOPS `year` 參數對應「申報年度」而非「年報所屬會計年度」，兩者常有一年落差，程式化批次
   抓取需以回應中檔名的西元年份為準，此為容易出錯的實作細節。
5. 歷史回填深度受題材本身的時效性限制（新興題材在更早年度的正式文件中本來就不會被提及），
   非單純的資料源覆蓋率問題，兩種限制的性質不同，不可混為一談。
