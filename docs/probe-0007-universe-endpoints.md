# Probe 0007: Universe 客觀化全市場篩選 — 端點探查

狀態：探查完成（供 ADR 0007「每月 PIT universe 快照」決策參考）
探查日期：2026-07-04
探查方式：實際打 API（Python 3.12 + requests），非查文件猜測。FinMind 每請求間 sleep ≥3 秒，單一 dataset 抽測 3-5 檔。

## 背景

要建「每月 PIT universe 快照」：母體=全上市櫃含下市股 → 硬篩（上市滿12月、流動性門檻、產業分類碼）。
關鍵架構問題：能否用「一次呼叫拿全市場一個月」的批次端點（138 個月＝138 次呼叫），而非逐檔打（2000 檔×138 月＝不可行）。

---

## 1. FinMind `TaiwanStockInfo`

**端點**：`GET https://api.finmindtrade.com/api/v4/data?dataset=TaiwanStockInfo`

**回應欄位**：`industry_category`, `stock_id`, `stock_name`, `type`, `date`

**筆數**：4276 筆
**type 分佈**：`twse`（上市）2380、`tpex`（上櫃）1367、`emerging`（興櫃）529
**industry_category 分類值**：共 57 種（含 ETF/ETN/Index/存託憑證等非個股類別），個股產業分類約 40 餘種，如「半導體業」「電子零組件業」「金融保險」「建材營造」等，命名與 TWSE/TPEx 官方產業分類一致。

**是否含已下市股**：**含**。實測：
- 3474 華亞科（2016年12月併入美光下市）→ 在名單中，`date` 欄位停在 `2024-12-04`（明顯是最後一次被更新的日期戳，非上市日），代表資料庫保留了歷史股票、只是不再更新。
- 8163 達方、2498 宏達電、2489 瑞軒、5439 高技、2363 矽統、4938 和碩 → 皆為現存上市股（原先猜測的下市代號中，只有 3474 是真下市，其餘仍在市，已修正樣本）。

**結論：可用**。TaiwanStockInfo 含歷史下市股，但無法從此端點單獨區分「現在還在市」vs「已下市」（需要交叉比對第 2 項下市清單，或看 `date` 是否停滯於過去）。

## 2. 下市名單來源（TWSE / TPEx）

### TWSE：`GET https://openapi.twse.com.tw/v1/company/suspendListingCsvAndHtml`

**回應欄位**：`DelistingDate`（民國年/月/日，如 `115/06/23`）、`Company`、`Code`

**筆數**：264 筆，涵蓋民國090/01/20（2001-01-20）至115/06/23（2026-06-23）
**樣本**：3474 華亞科 → `DelistingDate: 105/12/06`（2016-12-06），與 TaiwanStockPrice 最後交易日 2016-11-29 吻合（下市生效日前最後交易日）。

**結論：可用**。TWSE 上市股下市名單完整、含代號+下市日期，264 筆一次拿到。

### TPEx（上櫃）：**未找到對應端點**

掃描 TPEx openapi 全部 225 個路徑（`https://www.tpex.org.tw/openapi/swagger.json`），逐一比對 summary/description，只找到：
- `tpex_spendi_today` / `tpex_spendi_history`：暫停/恢復交易（trading halt，非永久下市）
- `tpex_cmode`：變更交易/分盤交易/管理股票/停止交易資訊
- `mopsfin_t187ap26_O`：經營權異動且營業範圍重大變更停止買賣公司（範圍窄，非通用下市清單）

**沒有**任何等同 TWSE `suspendListingCsvAndHtml` 的「終止上櫃公司完整歷史清單」端點。

**結論：不可用（上櫃側有缺口）**。這是明確限制，需記錄：上櫃下市股清單目前無官方批次端點可得，若要覆蓋上櫃下市股需另尋替代（如公開資訊觀測站人工整理、或用 FinMind TaiwanStockInfo 的 `type=tpex` + `date` 停滯訊號間接推斷，準確度較低）。

## 3. FinMind `TaiwanStockPrice` 對已下市股

**端點**：`GET .../data?dataset=TaiwanStockPrice&data_id={code}&start_date=...&end_date=...`

**實測 3474 華亞科**（2015-01-01 ~ 2017-12-31）：465 筆，首日 2015-01-05，末日 **2016-11-29**（下市日 2016-12-06 前的最後交易日，完全吻合）。

**實測 2358 廷鑫**（近期下市樣本，官方下市日 2024-11-19）：放寬查詢至 2020-01-01~2024-12-31 共 1033 筆，但末日僅到 **2024-04-03**，與官方下市日相差約 7.5 個月的空窗（該股下市前經歷長期停牌整理，此為個股特性非資料缺失）。

**結論：可用，但有重要限制**：FinMind 資料涵蓋到「最後實際成交日」，不等於「正式下市日」；財務危機/處置股常見停牌後才走完下市程序，兩者可能有數月落差。用月底 PIT 快照篩選「流動性門檻」時，這類股會自然因近期無成交量被篩掉，反而是預期內行為，但若用「是否已下市」做母體篩選需以下市清單（第2項）為準，不能只看價格資料斷點。

## 4. FinMind `TaiwanStockMonthRevenue` 對已下市股

**實測 3474 華亞科**（2015-2017）：**0 筆**。推測因華亞科為 DR/合資特殊股權結構，或美光合併後不適用一般月營收申報規則，此為個案而非普遍缺失。

**實測 2358 廷鑫**（2023-01~2024-12）：**23 筆**，首筆 `2023-01`（對應 2022-12 營收），末筆 `date: 2024-11-01, revenue_month: 10, revenue_year: 2024`（即2024年10月營收，下市前一個月），`revenue: 0`（可能該月已停止實質申報或財務異常歸零）。

**結論：可用（以 2358 為代表性樣本），但需注意個股例外**（如 3474 這類特殊股權結構公司可能無月營收資料，需在管線中容許「查無資料」而非報錯中止，與既有 ADR 0005「no-fabrication fail loud」原則一致——查無資料時應顯性標記缺值，不可用 0 或估算值填補）。

## 5. 整市場批次端點（全篩架構關鍵）

### 5a. TWSE 每日收盤行情（全部）——`exchangeReport/MI_INDEX`

**端點**：`GET https://www.twse.com.tw/exchangeReport/MI_INDEX?response=json&date=YYYYMMDD&type=ALLBUT0999`

**驗證可指定歷史日期**：
- `date=20240531` → 回傳 10 個表格，其中表格8「每日收盤行情(全部)」1241 筆（含 ETF/存託憑證等全部證券，非純個股）
- `date=20140530`（10年前）→ 同表格 901 筆，證實可回溯至少到 2014 年
- `date=20161129`（華亞科下市前）→ 975 筆，且**含 3474 華亞科**（收盤價 29.80，與 FinMind 對照吻合）

**回應欄位**（表格8 `fields`）：證券代號、證券名稱、成交股數、成交筆數、成交金額、開盤價、最高價、最低價、收盤價、漲跌(+/-)、漲跌價差、最後揭示買價/量、最後揭示賣價/量、本益比

**結論：可用，且是本次探查最關鍵的正面發現**。一次呼叫可拿全市場（上市）當日所有證券的收盤價+成交金額，且能指定任意歷史月底日期，並且在股票下市前的日期範圍內仍含該股。這代表 138 個月的回填只需 138 次 TWSE 呼叫（一年一次月底快照），不需要 2000 檔 × 138 月的逐檔窮舉。

### 5b. TWSE 個股月成交資訊 `FMSRFK`——確認為逐檔查詢

**端點**：`GET https://www.twse.com.tw/exchangeReport/FMSRFK?response=json&date=YYYYMMDD&stockNo={code}`

實測 stockNo=2330：回傳該股近12個月的月度統計（最高價/最低價/加權平均價/成交筆數/成交金額/週轉率），**確認為單檔逐月時間序列，非全市場批次**。

**結論：不可用作全市場批次替代**（本身設計就是逐檔用途，5a 的 MI_INDEX 才是月底快照的正確選擇）。

### 5c. TPEx 上櫃全市場行情——**歷史日期查詢已失效**

**新版 openapi** `GET https://www.tpex.org.tw/openapi/v1/tpex_mainboard_quotes`：回傳 1012 筆，但**僅當日資料**（`Date: 1150703`，即查詢當下的民國日期），無日期參數可指定。

**舊版傳統查詢** `GET https://www.tpex.org.tw/web/stock/aftertrading/daily_close_quotes/stk_quote_result.php?l=zh-tw&d=113/05/31&se=EW&o=json`：實測傳入 `d=113/05/31`（2024-05-31）等歷史日期參數，**回應內的 `date` 欄位仍固定回傳查詢當下日期（20260703）**，證實此端點的日期參數目前已被忽略/失效，只回傳「今天」的資料。嘗試多種參數名稱組合（`d`/`date`、加 `se=AL`）結果相同。

**結論：不可用**。TPEx 目前沒有可運作的「指定歷史日期的全市場批次行情」端點，這是本次探查發現的第二個重要缺口（上櫃側批次回填架構受阻）。若要補上櫃股歷史月底快照，替代方案：
- (a) 用 FinMind `TaiwanStockPrice` 逐檔抓上櫃股（約1367檔 tpex + 529 emerging，但 emerging 通常不列入 universe），對 138 個月回填仍是「檔數 × 月數」量級，量大但 FinMind 免費層以合理節奏（每檔間隔數秒）分散在多天執行是可行的，只是耗時遠高於 TWSE 上市股的批次方案；
- (b) 持續關注 TPEx openapi 是否日後補上歷史批次端點。

### 5d. 市值資料

**TWSE 開放資料 `opendata/t187ap03_L`（上市公司基本資料）**：
- 筆數：1089 筆（僅**現存**上市公司，不含已下市股）
- 欄位含：出表日期、公司代號、產業別、上市日期、實收資本額、已發行普通股數或TDR原股發行股數 等
- 可用「已發行股數 × MI_INDEX 收盤價」自算當前市值

**結論：部分可用**。此端點只反映「現在」的股本，**沒有歷史股本時間序列**（除非另外解析每季 XBRL 財報的股本欄位，或 t187ap07 系列季報資產負債表的「股本」欄位按季重建，工程量較大）。若 universe 篩選需要「當月時點市值」，用「當前股本 × 當月收盤價」回溯會有股本已變動（增資/減資/股票股利）的失真風險，尤其對曾大幅增減資的公司誤差較大。已下市股完全查不到股本（不在 1089 筆內），需退回 FinMind 或財報資料源。

## 6. 產業分類的歷史一致性

**探查結論：沒有找到「歷史時點產業分類」的公開資料源。**

FinMind `TaiwanStockInfo` 的 `industry_category` 欄位本質上是「資料庫當前快照」（每筆有 `date` 欄位，但那是「最後更新日」而非「該分類生效區間」）。TWSE/TPEx 官方基本資料端點（如 `t187ap03_L` 的「產業別」欄位）同樣只反映當前分類。

未發現任何端點提供「某公司在 2018 年時的產業分類 vs 現在的產業分類」這種時間序列版本。

**誠實聲明（需寫入 ADR）**：本探查未能找到歷史時點產業分類資料源。已知台股產業分類異動事件確實存在（如上市公司變更所屬產業類別、電子業內部子分類调整等），但發生頻率低、非常態。若 universe 篩選的「產業分類碼」硬篩門檻採用**現行分類回溯套用到歷史月份**，會有小比例個股在異動發生前後被錯誤分類/歸類到現在的產業別而非當時的產業別。此為已知限制、非資料遺漏，建議在 ADR 中明確聲明並評估此限制對篩選結果的影響幅度為可接受（分類異動率低），但不宜宣稱「歷史分類完全準確」。

## 7. FinMind 限流實測

**測試方式**：連續對 5 檔（2330、2317、2454、2412、1301）呼叫 `TaiwanStockPrice`，每次間隔 sleep 3 秒。

**結果**：5 次請求全部 `status 200`、`msg: success`，**無 402/429**。

**Token 檢查**：檢查專案 `.env`（`C:\CLAUDE\市場熱度分析整理\.env`），**未設定 `FINMIND_TOKEN`**（即目前走免費匿名層，無 API token）。

**結論：可用**。在 sleep ≥3 秒的溫和節奏下，免費層短時間內（5次請求內）未觸發限流。此結果與既有 `ingest.py` 程式碼中「FinMind 免費有限流 → 逐檔抓取之間 sleep」的既定慣例一致，建議延續現行節奏設計，不需要額外申請 token（若未來要大量回填上櫃股逐檔資料，才需要評估是否申請 token 提升額度）。

## 建議架構

**批次優先、混合為輔**：上市股（TWSE）用 `exchangeReport/MI_INDEX?type=ALLBUT0999` 做「每月月底一次呼叫」的批次快照，138 個月 = 138 次 TWSE 呼叫，這是可行且高效的核心路徑；上櫃股（TPEx）因官方歷史批次端點目前失效（第5c項），暫時只能退回 FinMind `TaiwanStockPrice` 逐檔抓取，用既有 `ingest.py` 的溫和節奏（sleep 3秒+）分散執行。

**估算總請求數**：上市股批次路徑 138 次（TWSE MI_INDEX，一年一度可並行跑多年份不需逐月依序）；上櫃股逐檔路徑約 1300~1400 檔（不含興櫃）× 需要的月度覆蓋（若用單次呼叫拿多年區間如 `start_date`/`end_date` 涵蓋 138 個月的做法，FinMind 一次呼叫可回傳整個區間序列，故上櫃股只需**約 1300~1400 次 FinMind 呼叫**，而非 1300×138，因為 FinMind 用日期區間查詢即可一次拿到全部歷史，不必逐月呼叫）。下市名單（TWSE 264筆）與 TaiwanStockInfo（4276筆）各 1 次呼叫即可。

**預估耗時**：TWSE 批次路徑 138 次請求，無嚴格限流顧慮（官方 openapi 非 FinMind），可在數十分鐘內跑完；上櫃股逐檔路徑約 1300~1400 次 FinMind 呼叫、每次間隔 3 秒，約需 1300×3秒 ≈ 65 分鐘（不含資料處理時間），建議分批執行並容錯重試。

**已知缺口需在 ADR 誠實聲明**：(1) TPEx 無下市清單批次端點、無歷史批次行情端點，上櫃側覆蓋度與可靠度低於上市側；(2) 無歷史時點產業分類資料源，只能用現行分類回溯；(3) 市值需自算且無歷史股本序列，用現行股本回溯有失真風險；(4) 個股資料可能因停牌等原因，最後交易日早於正式下市日數月，不可混淆兩者。
